## 작성 가이드

### 비즈니스 시나리오
- **실무 중심**: 실제 서비스에서 발생하는 상황 묘사
- **복잡성 강조**: 왜 이 문제가 Medium인지 설명
- **맥락 제공**: 단순 함수 설명이 아닌 시스템 맥락

### 위험성 테이블
- **4개 이상**: Medium은 버그 유형이 다양함
- **정량화**: "고객 불만" → "월 1000건 CS 인입, 처리 비용 500만원"

### 함수 명세
- **파라미터 테이블**: 복잡한 입력은 표로 정리
- **규칙 그룹화**: 관련 규칙끼리 묶어서 설명
- **상호작용 명시**: 규칙 간 우선순위나 영향 관계

### 테스트 가이드
- **핵심만**: 모든 것을 알려주지 않음
- **관점 제시**: "경계값 + 조합 + 예외" 같은 관점 안내
- **스스로 발견**: 구체적 테스트 케이스는 수험자가 설계

```markdown
**복잡성 포인트**:
이 함수는 RFC 5322 표준과 실무 서비스 정책 사이의 균형을 맞춰야 합니다. 너무 엄격하면 정상 이메일을 거부하고, 너무 느슨하면 발송 실패와 바운스율 증가로 이어집니다.
```

## Medium 특징

| 항목 | Easy와의 차이 |
|------|-------------|
| 시나리오 | 단순 → 복잡한 비즈니스 맥락 |
| 힌트 | 친절 → 핵심만 |
| 규칙 | 1-2개 → 다중 규칙 조합 |
| 테스트 기법 | 기본 → 파라미터화, Mock 필요 |
| 뮤턴트 | 단순 버그 → 조합/상태 버그 |

```

### 2. 상태 기반 테스트 (State-based Testing)
```python
# [상태 조합 설명]

    ([조합3]),  # [시나리오3 - 함정]

```

### 3. 동등 분할 (Equivalence Partitioning)
```python
# [분할 설명]
def test_[partition_name]():
    [items/inputs] = [...]
    # [핵심 검증 포인트]
```

### 4. 부수효과/상태 누출 테스트
```python
import copy

def test_no_input_mutation_and_no_hidden_state():
    # [설명]
    [inputs] = [...]
    _inputs_copy = copy.deepcopy([inputs])

    result1 = [함수명]([inputs])
    result2 = [함수명]([inputs])  # 동일 입력 재호출

    assert [inputs] == _inputs_copy  # 입력 변경 없음

## 작성 가이드

### 비즈니스 시나리오
- **복잡성 전달**: 왜 이 문제가 어려운지 첫 문단에서 전달
- **다층 규칙 언급**: 규칙이 어떻게 얽혀있는지 개략 설명
- **실제 장애 사례**: 가능하면 실제 발생했던 버그 유형 언급

### 함수 명세
- **흐름도 필수**: 규칙 적용 순서를 시각화
- **테이블 활용**: 복잡한 규칙은 표로 정리
- **함정 명시**: 각 규칙에서 실수하기 쉬운 부분 힌트

### 테스트 전략
- **코드 예시**: Hard는 코드 스니펫으로 방향 제시
- **관점 제시**: 어떤 테스트 기법이 필요한지
- **최소 힌트**: 구체적 값은 제공하지 않음

### 테스트 케이스 분류 테이블
- **난이도 표시**: ★로 상대적 난이도 표시
- **포인트 명시**: 무엇을 검증해야 하는지 키워드

당신은 **쿠팡**의 결제 시스템 QA 엔지니어입니다. `calculate_cart_total` 함수는 장바구니의 최종 결제 금액을 계산하며, **다층 할인 규칙**과 **쿠폰 정책**이 복잡하게 얽혀 있습니다.

## Hard 특징

| 항목 | Medium과의 차이 |
|------|---------------|
| 규칙 | 다중 → 다층 (순서 의존) |
| 상태 | 단순 → 숨겨진 상태, 부수효과 |
| 테스트 | 조합 → 상태 기반, 비결정성 |
| 힌트 | 관점 → 코드 스켈레톤 |
| 뮤턴트 | 조합 버그 → 미묘한 상태 버그 |

## Hard 뮤턴트 특성

Hard 문제의 buggy_implementations는 다음 특성을 가져야 합니다:

1. **Off-by-one (경계값)**: >= vs > 같은 미묘한 차이
2. **상태 조합 오류**: 특정 조건 조합에서만 발생
3. **정책 위반**: 비즈니스 규칙 해석 오류
4. **Silent Failure**: 예외 없이 잘못된 결과
5. **Hidden State**: 함수 간 숨겨진 상태 공유

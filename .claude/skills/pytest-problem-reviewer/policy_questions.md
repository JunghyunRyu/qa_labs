## 1. 기본 정책(임시 Default)
> 아직 결정되지 않았더라도, 리뷰어는 아래 기본값을 사용합니다.
> 추후 결정이 내려지면 "2) 결정 필요"에서 "4) 결정 로그"로 이동합니다.

### 1-1. 예외 타입 정책
- 타입 오류: TypeError
- 값/형식/범위 오류: ValueError
- 구조 오류(스키마/헤더/필수키): ValueError
- 에러 메시지: exact match 강제 금지(키워드 수준만 권장)

### 1-2. bool 처리 정책
- int 문맥에서 bool은 기본적으로 **금지** (명시적으로 허용하는 문제만 예외)

### 1-3. 문자열/공백 정규화 기본값
- 별도 명시 없으면: 문자열 필드에 strip() 적용 여부는 문제 스펙에 반드시 명시
- “등/기타/…” 표현 금지: 허용 집합을 나열

### 1-4. 날짜/시간 검증 범위 기본값
- 별도 명시 없으면: 형식만 검증(예: YYYY-MM-DD), 달력 유효성은 검증하지 않음

### 1-5. 파싱(CSV/JSON) 기본값
- 공백 줄: 스펙에 “무시/에러”를 명시
- 줄바꿈: \n만 지원인지, \r\n 포함인지 스펙에 명시
- CSV 따옴표/이스케이프: 지원 범위를 스펙에 명시 (미명시 시 단순 입력만)

## 2. 결정 필요(Open Questions)
> 플랫폼 전체 일관성을 위해 반드시 결정이 필요한 항목.
> 각 항목은 "권장안"과 "대안"을 함께 기록합니다.

### Q1. 예외 타입 통일 전략
- 질문: 타입 오류를 TypeError로 유지할 것인가? 아니면 모든 실패를 ValueError로 통일할 것인가?
- 권장안: 타입 오류 → TypeError, 값/형식/범위 → ValueError
- 대안: 모든 실패 → ValueError(일관성↑, Python 관례↓)
- 영향 범위: 모든 문제/테스트 템플릿/채점기

### Q2. 에러 메시지 강제 범위
- 질문: 에러 메시지를 전혀 강제하지 않을 것인가? 키워드 포함 정도는 허용할 것인가?
- 권장안: exact match 금지, 키워드 포함 정도만 “권장”
- 대안: 메시지 형식 강제(채점 취약/버그풀 다양성 저하)

### Q3. bool 처리 기본 정책
- 질문: int 입력에서 bool을 기본 금지로 둘 것인가?
- 권장안: 기본 금지 (명시적으로 허용하는 문제만 예외)
- 대안: Python 기본 타입 계층을 그대로 허용 (수험자 혼선↑)

### Q4. 날짜 검증 범위(형식 vs 의미)
- 질문: 날짜/시간 관련 문제에서 달력 유효성(2/30 같은 날짜)까지 검증할 것인가?
- 권장안: Hard 이상에서만 의미 검증 요구, 그 외는 형식 검증만
- 대안: 항상 의미 검증(구현 부담↑)

### Q5. CSV 파싱 지원 범위
- 질문: 표준 csv 규격(따옴표/쉼표 포함 필드)을 지원 요구할 것인가?
- 권장안: Easy 이하에서는 단순 CSV만, Hard에서만 표준 csv 지원 명시
- 대안: 항상 표준 csv(출제/정답 구현 복잡도↑)

### Q6. 공백 줄/트레일링 콤마/빈 컬럼 처리 규칙
- 질문: “의미 있는 줄” 정의 및 빈 컬럼 처리에서 기본 규칙을 가질 것인가?
- 권장안: 문제마다 명시(파싱류는 반드시 명시)
- 대안: 플랫폼 기본값으로 통일(문제 작성 편의↑)

## 3. 정책 충돌 발생 시 처리 규칙
- 리뷰어는 문제 스펙이 정책과 충돌하면:
  1) 스펙을 정책에 맞추는 변경안을 제시하거나
  2) “정책 예외”로 분류하고, 이유를 명시한다.
- 예외는 반드시 “4. 결정 로그”에 남긴다.

## 4. 결정 로그(Decision Log)
> 결정이 내려진 항목을 기록합니다.

### [D-001] 예외 타입 정책
- 결정일: 2026-01-09
- 결정: 타입 오류 → TypeError / 값·형식·범위 오류 → ValueError
- 근거: Python 관례 준수, 타입 힌트와 일관성 유지
- 적용 범위: 모든 문제
- 마이그레이션 필요: No (현행 유지)

### [D-002] 에러 메시지 정책
- 결정일: 2026-01-09
- 결정: exact match 금지, 키워드 포함만 권장
- 근거: 채점 안정성 확보 + 버그풀 다양성 유지
- 적용 범위: 모든 문제
- 마이그레이션 필요: No

### [D-003] bool 처리 정책
- 결정일: 2026-01-09
- 결정: int 문맥에서 bool 기본 금지, 허용 시 명시
- 근거: 명확한 계약, 수험자 혼선 방지
- 적용 범위: int 파라미터 포함 문제
- 마이그레이션 필요: 기존 문제 점검 필요

### [D-004] 날짜 검증 범위 정책
- 결정일: 2026-01-09
- 결정: 난이도별 기준 적용
  - Very Easy/Easy: 형식만 (YYYY-MM-DD 패턴)
  - Medium: 형식 + 월(1-12), 일(1-31) 범위
  - Hard: 완전 달력 유효성 (윤년 포함)
- 근거: 난이도별 적절한 복잡도 부여
- 적용 범위: 날짜 관련 문제
- 마이그레이션 필요: 해당 문제 점검

### [D-005] CSV 파싱 지원 범위 정책
- 결정일: 2026-01-09
- 결정: 난이도별 기준 적용
  - Very Easy/Easy: 단순 CSV (콤마 구분만, 필드 내 콤마 없음)
  - Medium: 따옴표 필드 지원 (필드 내 콤마 허용)
  - Hard: RFC 4180 표준 CSV (이스케이프, 멀티라인 포함)
- 근거: 난이도별 적절한 복잡도 부여
- 적용 범위: CSV 파싱 문제
- 마이그레이션 필요: 해당 문제 점검

### [D-006] 공백/빈값 처리 정책
- 결정일: 2026-01-09
- 결정: 파싱 문제마다 반드시 명시
  - 공백 줄 처리: 무시 / 에러 / 빈 레코드
  - 빈 필드: 빈 문자열 / None / 제거
  - 트레일링 콤마: 허용 / 에러
  - 줄바꿈 문자: \n만 / \r\n 포함
- 근거: 모호성 제거, 채점 안정성 확보
- 적용 범위: 파싱류 문제
- 마이그레이션 필요: 기존 파싱 문제 점검
